# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

SvelteKit (Svelte 4, TypeScript) web app for reordering, shuffling and copying a user's Spotify playlists. Auth is Spotify OAuth via `arctic` + `lucia` sessions stored in SQLite (`better-sqlite3`). UI uses shadcn-svelte (`bits-ui`) components and Tailwind.

## Commands

```bash
npm install
npm run dev            # dev server (add `-- --host` to listen on all addresses, e.g. from a VM/WSL)
npm run build
npm run check          # svelte-kit sync + svelte-check (type checking)
npm run lint           # eslint
```

There is no test suite.

A `.env` with `CLIENT_ID`, `CLIENT_SECRET`, `REDIRECT_URI` (from a Spotify developer app) is required; they are imported via `$env/static/private`, so the app won't build without them. The redirect URI must point at `/api/auth/callback`.

## Architecture

**Auth and request flow** (`src/hooks.server.ts`): every request without a session cookie is redirected to `/login`, except `/login` and `/api/auth/*`. Spotify access/refresh tokens live on the lucia *session* row (not the user), exposed as `event.locals.session.access_token`. The hook refreshes the Spotify token when it's within 5 minutes of expiry, updating both the DB and the in-memory session. Server code calls the Spotify Web API directly with `fetch` and a `Bearer` header — there is no Spotify SDK.

Note the two user identifiers: `locals.user.id` is the local lucia id (used as the key in all local DB tables), while `locals.user.spotify_id` is used for Spotify API calls and ownership checks.

**Database** (`src/lib/db.ts`): opens `app.db` in the working directory and creates tables with `CREATE TABLE IF NOT EXISTS` on import. There are no migrations — schema changes to an existing table won't apply to an existing `app.db` (delete it locally to reset). Besides lucia's `user`/`session`, it stores per-user playlist visibility (`user_hidden_playlists`) and a saved source→target playlist mapping (`user_playlist_targets`). All query helpers live in this file.

**Routes**:
- `src/routes/playlist/+layout.server.ts` fetches *all* of the user's playlists (paginated 50 at a time, pages after the first fetched in parallel), then merges in local visibility and saved targets, and sorts by name. This layout data (`data.playlists`) is shared by the playlist index and the `[id]` editor.
- `src/routes/playlist/+page.*` lists playlists and toggles visibility via a superforms/zod form action (`hidePlaylists`, schema in `schema.ts`).
- `src/routes/playlist/[id]/` is the editor: loads all tracks (same pagination pattern), assigns each a synthetic `id` of `${track.id}:${index}` because playlists may contain duplicates. All editing (drag-and-drop reorder, shuffle, column sort with restorable custom order) is client-side on `data.tracks`; nothing is persisted until commit.
- Commit: the client POSTs track URIs to `/api/commit`, which *replaces* the target playlist's tracks via Spotify `PUT /playlists/{id}/tracks` (capped at 100 URIs — the Spotify limit for that call). On success it POSTs to `/api/save_target` to remember the target. A playlist can be committed to directly only if it's owned by the user, not collaborative and ≤100 tracks; otherwise a "target" playlist must be chosen (targets are filtered to committable, visible playlists).

**Track list** (`[id]/TrackList.svelte`, `Track.svelte`): virtualized with `@tanstack/svelte-virtual`; drag-and-drop uses Atlassian `pragmatic-drag-and-drop` (`draggable`/`dropTargetForElements` per row, `monitorForElements` + `reorderWithEdge` in the list). `track-data.ts` tags drag payloads with a private symbol.

**Types**: `src/lib/api_types.ts` holds a trimmed copy of Spotify Web API types, extended with app fields (`Playlist.isVisible`, `Playlist.targetId`).

**UI components**: `src/lib/components/ui/` is generated by shadcn-svelte (config in `components.json`); add new ones with the shadcn-svelte CLI rather than writing by hand. Icons come from `unplugin-icons` via `~icons/material-symbols/<name>` imports, plus `lucide-svelte`.
